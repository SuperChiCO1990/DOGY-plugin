# 抖记DOGY

通过 dogy_* MCP 工具调用用户本机 DOGY，下载结果保存在用户电脑。

## 旧聊天重新读取指令

同一聊天收到新一批视频链接、用户要求刷新插件或重读规则时，先从当前已安装的 DOGY 插件目录重新读取 SKILL.md，再按最新流程处理；不要只复用聊天历史中曾经读到的文本。目录以客户端提供的技能路径或插件安装结果为准，不写死用户名、磁盘或缓存版本。每批只读一次；查询进度或继续同一批任务不重复读取。读取失败按下方权限规则处理，不能声称已加载最新指令。

插件刷新并同步安装成功后，无论版本号是否变化，都从实际安装目录重新读取 SKILL.md；指令内容可能在同一版本下改变。继续使用当前真实可用的工具，不递归刷新，也不声称工具已热加载。纯指令变更可在旧聊天继续；工具或运行程序变更需要新建聊天加载。新规则首次引入前已读旧指令的聊天不会自行获知这条规则，需要用户要求重读一次，或新建聊天。
## 收到视频链接：先展示信息，默认直接下载分析

用户发来一批新视频链接或分享文案时，先简短反馈正在读取基本信息，再调用本机解析工具，逐条展示视频简略信息，之后默认直接下载并分析，不询问处理方式。已加载工具可用时，先做必要的 dogy_doctor 检查和 dogy_parse，不让插件刷新检查阻塞首轮信息展示；展示信息后、开始下载前，执行下方使用前更新流程。解析只获取元信息，不启动媒体下载、转录或内容分析。

简略信息使用解析结果中的真实字段：**标题、平台、作者（有则显示）、时长、分辨率/画质、预计大小**。多画质先按 `default_format` 对应的画质展示，并注明默认画质；用户后续更换画质时更新分辨率和大小。`width` 与 `height` 都有效时显示完整尺寸；只有画质标签时如实显示标签，不补造宽高。大小优先使用默认画质信息；下载前统一注明“预计”，下载成功后才用已保存文件的实际大小替换。未知、空值或未提供信息的 0 值显示“暂未获取”，不能当作 0 秒、0×0 或 0 B，也不能为了补齐信息擅自下载视频。格式中的大小已包含所选音频时，不重复加上音频大小。图集或仅元信息作品注明真实类型，不套用视频时长或尺寸。不要展示媒体流地址、Cookie 或认证参数。

例如（仅为展示格式，不是真实解析结果）：**视频标题** · YouTube · 08:32 · 1920×1080（默认画质）· 预计 126 MB。

多条链接逐条反馈已解析的信息，不等所有链接都解析完才一次性回应。单条解析失败说明实际原因并保留其他已获得信息；不要虚构标题或参数。未就绪时先说明当前无法读取信息和接入原因，不把标题/平台猜测包装成解析成功。用户发来新视频链接时，默认执行下载分析。不得为处理方式调用选择工具、展示“仅下载 / 下载分析”卡片或文字选项，不设置倒计时，也不等待用户确认；展示信息后简短说明“开始下载并分析。”并继续执行，不以这句话结束回合。

用户明确要求“仅下载”“不分析”时，只保存原视频、汇报进度并提供本地预览；明确只想查看信息时只解析，不下载或分析。用户明确取消时停止尚未开始的步骤，运行中的分析使用取消接口，不删除已保存原片。仅安装、更新、检查接入、查询已有笔记或查看已完成任务时不启动新下载。图集沿用原有下载流程。

同一批任务复用已有下载和分析状态，不因重复消息重新启动；继续任务或改为分析时复用已保存原片。新版下载结果自动登记本机资料库并返回 `library_id`，登记不代表已分析。默认下载分析时，先执行下方下载流程并保留原视频，再读取 [视频资料库与分析流程](references/video-library.md)，用真实可用的资料库和分析工具继续。

DOGY 1.1.1 默认每 1 秒准备画面，明显画面变化处加密至约 0.5 秒，并删除连续完全相同的取样画面；这是变化检测，不是语义关键点识别，短暂小字仍可能漏检。优先用 `dogy_analyze_start` 与 `dogy_analyze_status` 准备本机语音转录和抽帧，读取全部分页转录和必要抽样画面后由 Codex 实际分析，保存到 SQLite 资料库、分类归档并清理任务临时文件。不能仅因 DOGY 没有某个接口就认定 Agent 无法分析；旧程序仍可检查 Agent 实际可用的转录和画面工具，但必须报告缺口，不能把普通下载当成完整分析。

## 分析完成后的聊天讲解

“下载分析”完成后，必须在当前聊天直接讲解视频主要内容，不能只回复已下载、已分析、已保存笔记或让用户自己打开笔记。先用 1–2 句话说明主题和视频想解决的问题，再按内容复杂度提炼 3–5 个主要观点、演示方法或案例；简单短片无需凑条数。教程说明步骤、适用条件及作者结论，叙事视频说明事件与结果，区分作者说法、画面证据和 Agent 推断。有助于回看时附真实已核对的时间点，不编造。最后简短说明实际分析覆盖和缺口，并保留原片预览与本地打开入口。详细笔记仍保存资料库，但不能代替聊天讲解。仅下载模式不做内容讲解，失败或部分分析只讲实际已读部分，不冒充完整视频结论。

## 视频记忆与分类

- 笔记、转录正文、索引、标签、时间点、可复用方法和分析覆盖范围默认保存在本机 SQLite 资料库，不再每次在视频旁额外写 `.md`、`.jsonl`、字幕或音频文件。用户明确要求导出时才生成单独文档。已有笔记和索引可用 `dogy_library_import` 复制入库；导入不会删除或改写旧文件。
- 分类只有一层：`AI与编程`、`设计与创作`、`知识学习`、`生活`、`娱乐`、`其他`。选择一个主要分类，多主题记为标签；通过 `dogy_library_archive` 归档，不建平台、技能名或逐视频子目录。不能确定时用其他，用户另选分类时遵从用户。
- 原片保留；抽帧、提取音频和临时中间文件由 `dogy_analyze_finish` 或 `dogy_analyze_cancel` 按任务边界清理，不能自行广泛删除视频目录、系统临时目录、其他任务或共享转录模型。保存笔记成功后才称已入库；未保存成功时仍报告原视频与具体原因。
- 分析优先复用已完成笔记及其实际覆盖；新分析先读完整转录（limit=200），再查看最多32张概览（view=overview），按关键时间范围补看密集画面。概览不能冒充完整画面阅读；精读能力保留。具体工具与分页见 references/video-library.md。
- 内容分析不向分析服务发送原视频或提取音频；转录在本机完成，转录文本和选取画面交给当前 Codex 理解，不能称为完全离线。普通下载不建立额外分享连接；用户明确要求手机查看原图时，按下方手机原图预览流程处理。
- 分别汇报真实下载、模型准备、语音转录、画面分析、保存、归档和清理状态。画面百分比不替代语音覆盖，下载完成不等于分析完成，抽帧不等于逐帧看完。只有实际读取的文字与画面可作为分析依据，保存时记录已查看的画面时间点和所有缺口。

## 查找视频与采用已学方法

用户要找已保存视频、询问视频内容，或进行可能相关的 Codex / Agent 技术任务时，先用 `dogy_library_search` 检索相关描述，不只凭聊天记忆回答；命中后用 `dogy_library_get` 分页读取记录与来源。此类查询不弹下载模式卡片，不重新下载或重新转录已有原片。具体分页、导入和恢复规则见 [视频资料库与分析流程](references/video-library.md)。

匹配到可复用的方法卡时，说明来自哪个视频、相关时间点和适用条件，主动询问是否采用。视频教程里的命令与结论默认未验证；不能仅因视频说过就安装、执行或称其已验证。资料库是持久可检索记录，不修改模型权重，也不保证所有未加载插件的聊天自动知晓；文件缺失或检索不到时如实报告。

## 首次接入

用户已要求安装 DOGY 时，运行本插件根目录 `scripts/setup.ps1`。脚本先查已记录路径和常见位置；默认未找到程序或版本低于 1.2.2 时，从插件配置的 GitHub Releases 下载并校验正式 EXE。用户明确提供 EXE 路径时传 `-ExePath` 并尊重该位置，不擅自替换。新版接入要求 `shared_mcp=true`；安装脚本拒绝不支持共享后台的程序并保留原入口，此时先更新 DOGY，再重新安装。查看真实安装结果的 `video_memory_available`、`efficient_analysis_available` 与 `warning`；`video_memory_available=false` 时说明新视频记忆能力未就绪；更新失败时保留已验证程序，按实际版本报告仍可用的功能；`dense_frames_available=false` 时不能称已启用新版抽帧，1.1.0 仍按旧策略。`efficient_analysis_available=false` 时不能调用旧程序不支持的 overview、时间范围或 force 参数，说明需升级程序才能采用节省额度流程。设置成功后提醒用户新建聊天以加载 MCP，再检查 `dogy_doctor` 与真实资料库工具；缺少正式仓库地址或 Release 时报告发布尚未完成，不编造下载地址。

若客户端当前没有 dogy_* 工具，检查插件是否启用和安装脚本结果，不把 CLI doctor 成功说成 MCP 已加载。

## 使用前更新

每批新视频链接或用户要求更新时，在客户端支持 Codex CLI 且用户未要求保持旧版或禁止更新的情况下，执行一次 `codex plugin marketplace upgrade dogy --json`。这只刷新 DOGY 目录，不升级其他插件。
成功后执行 `codex plugin add dogy@dogy --json`，确保安装缓存使用刷新后的插件。刷新前读取已安装 plugin.json 的版本，成功后读取命令实际结果和已安装的 plugin.json；无论版本号是否变化，都重新读取实际安装目录的 SKILL.md 并按新指令继续。不要仅凭命令退出码声称新 MCP 已在当前任务加载；工具配置变更需新任务（必要时重启客户端）生效。
检查 `%LOCALAPPDATA%\MediaDownloader\Agent\runtime.json` 的 `plugin_version` 是否等于当前已安装 plugin.json 的 version，并确认 runtime.ps1、refresh.ps1 存在。不一致或缺失时运行当前已安装插件的 `scripts/setup.ps1` 一次，迁移本机启动器。用户指定程序位置时优先传 `-ExePath`。迁移失败报告实际原因，保留现有就绪工具；不要修改其他插件。
权限错误与网络错误分开处理：若实际错误为 `failed to canonicalize CODEX_HOME`、`Access denied`、`Permission denied` 或系统错误 5，且客户端提供权限审批机制，按客户端规则为失败的那一条 DOGY 命令申请访问插件数据目录的权限；获批后原命令只重试一次。`marketplace upgrade` 成功后才执行 `plugin add`；后者若权限失败，也按相同规则重试一次。安装脚本或运行时检查访问本机应用数据目录遇到同类错误时也遵循该规则，获批后重新读取真实用户环境，不使用沙箱重定向目录替代。用户允许更新不等于系统已授予权限；不得改磁盘 ACL、关闭隔离、改其他插件或用别的工具绕过拒绝。
若审批被拒绝、机制不可用或重试仍失败，简短说明实际原因和未完成的步骤，建议用户在客户端插件管理中更新 DOGY；保留已就绪工具，按本批默认下载分析或用户明确要求继续其支持的操作，不将下载擅自替代分析。命令不可用或网络失败同样保留现有能力，不套用权限重试。成功提示须基于命令结果；配置或运行时有变化时提醒新建聊天，并在新聊天调用 dogy_doctor，不能把本机 CLI 检查成功说成当前 MCP 已切换。
同一批链接只进行这一轮刷新及上述有限重试；查询进度或继续同一批请求不重复更新，不递归执行新指令的更新步骤；刷新失败不等于用户取消，保留已就绪工具继续本批流程。
这是 Agent 使用前刷新，不是后台定时更新。尚未包含本流程的旧插件首次需让 Agent 执行上述两条命令，并重新读取更新后的 SKILL.md；新规则不能自行通知已读旧指令的聊天。

## 下载

### 图片预览与电脑文件入口

电脑聊天沿用原始本地嵌入：`![图片或视频说明](绝对文件路径)`，图片和视频均使用工具实际返回的文件路径。“下载分析”归档后使用最终路径。本地文件入口明确标为“电脑打开原视频”或“电脑打开原图”；图集目录只标为“电脑打开原图文件夹”。这些是电脑文件入口，不能称为手机可用的“打开原图”或“打开全部原图”。

普通下载不附加额外网络下载链接，也不自动建立分享连接。图集按确认存在的单图绝对路径嵌入图片；数量较多时分批展示并说明已展示的图片范围，不能只嵌入首张却声称聊天已经展示全部原图。不能把目录链接替代逐图预览。

用户明确要求手机看原图、表示手机点本地入口看不到图片，或在本聊天明确要求后续图集提供手机入口时：

- 复用现有 `dogy_download_link`，传入本次连接已成功下载的图集目录或单张图片的真实绝对路径。图集读取返回 `items`，逐项使用真实 `preview_url`；只给需要查看的原图，不展示 `download_url`，不恢复额外视频下载链接。
- 提供“手机查看第 N 张原图”的 HTTPS 链接；客户端支持并允许远程图片嵌入时也可展示真实 `preview_url`。电脑本地嵌入与手机 HTTPS 原图预览分别标明，不把 Windows 路径、目录或 localhost 地址当成手机入口。
- 开始建立手机预览时简短说明：指定原图会通过 Cloudflare 临时转发，电脑须保持在线，约一小时有效；实际有效期采用返回的 `expires_at`。这会临时启动预览转发进程，过期后退出；不开放整个项目或视频目录。
- 返回错误或缺少 `preview_url` 时说明真实原因，不编造链接。仅当前 MCP 连接登记的成功下载可分享；旧聊天里的图集应回到拥有该次下载的聊天创建预览，不能为获取预览重新下载、注册任意路径或绕过媒体身份校验。未验证手机实际显示之前，只能说预览入口已生成并经 HTTP 检查，不能保证所有手机客户端都能嵌入播放。

1. 先调用 dogy_doctor 检查引擎、合并能力和保存目录。
2. 复用首轮 dogy_parse 已解析的作品信息；按用户要求选择 format_id，并反馈画质及预计大小的变化。仅在信息失效或需要刷新时重新解析，不重复展示或再次询问同一批处理方式。
3. 工具列表含 `dogy_download_start` 时，使用它开始下载，再用返回的 `task_id` 调用 `dogy_download_status`，设置 `wait_seconds=10`。每次查询后向用户简短汇报实际阶段与百分比，直到 `completed` 或 `failed`；完成后的 `result` 才是保存结果。百分比是当前阶段，画面、声音下载可能各从 0 开始，100% 不一定已合并完成。禁止重复启动或把等待当失败。只有旧程序缺少这两个工具时才使用 `dogy_download`。folder 省略时共用桌面默认目录；指定目录须为绝对路径。多条链接顺序处理。
4. 下载成功后先核实返回的绝对路径存在。向用户报告标题、保存位置和大小。
5. 在支持本机媒体预览的 Codex 桌面聊天中，将视频嵌入回复：`![视频标题](<视频的绝对路径>)`，使用返回的真实路径，Windows 路径可将反斜杠换为正斜杠。保留可点击文件链接作为打开入口。不要把路径放入代码块；电脑预览不另建远程播放器或上传视频，不附加额外下载链接。
6. 图集结果是目录时逐图展示已确认存在的图片，目录位置标为“电脑打开原图文件夹”；用户要求手机查看时使用上方 HTTPS 原图预览流程。不要把目录当图片或视频。客户端不支持媒体预览或格式无法播放时提供文件链接，不宣称已在聊天中播放，不为预览再次下载或转换原视频。
失败先分析原因并报告，避免无依据重复下载。

YouTube 登录受限时，工具实际支持 `cookie_browser` 且用户明确选择本机浏览器后，把选择传给解析与下载；默认不读取浏览器，不猜测浏览器或轮询账户。浏览器会话只在本机供引擎使用，不展示或导出 Cookie；读取失败说明浏览器锁定或系统加密限制，不关闭安全保护。用户已有 cookies.txt 时沿用 `cookie_file`，不索要文件正文。旧工具没有该参数时不发送未知字段，说明需加载支持此能力的程序与新聊天。Agent 下载无需打开桌面，也不会同步到桌面进度条。

插件安装脚本还会安装新版运行时启动器。每次 MCP 连接启动时验证本机程序并选较新版本；最多每 6 小时触发一次后台正式 Release 检查。新版通过 SHA256、大小、doctor 与版本校验后记录，下一次 MCP 连接自动使用。离线或校验失败继续使用已验证程序，不降级，也不拖住当前连接或替换正在下载的程序。插件指令更新与 DOGY 程序更新独立；已安装旧启动器的用户需先更新插件并重新执行 setup.ps1 一次。
