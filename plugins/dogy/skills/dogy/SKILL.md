# 抖记DOGY

通过当前客户端真实提供的 `dogy_*` MCP 工具调用用户本机 DOGY；只使用工具 schema 中已有参数和真实返回值，结果保存在用户电脑。

## 入口与按需参考

- 每批新视频链接先从实际安装目录重读本文件一次；同批续办或查询进度不重复读取。刷新成功后，无论版本号是否变化，都重读实际安装副本，不递归刷新。
- 新链接按下方流程直接下载分析；下载前执行一次 DOGY 使用前更新。更新、安装、接入检查、权限或 YouTube 登录问题，读取 [接入与更新](references/setup-and-updates.md)。更新失败保留已就绪工具继续，工具变更需要新聊天加载，不能声称已经热加载。
- 分析、保存、归档、恢复、导入或检索笔记，读取 [视频资料库与分析流程](references/video-library.md)。普通媒体按 [本地媒体展示](references/media-preview.md)；仅在用户要求手机看原图时启用该参考中的 HTTPS 原图流程。

## 新链接：高清下载并分析

1. 简短反馈正在读取信息；必要时先 `dogy_doctor` 检查引擎、合并能力和保存目录，再 `dogy_parse`。解析只获取信息，不启动下载、转录或分析。多条链接逐条反馈，不等待全部解析完成。
2. 保存本条解析返回的 `parse_token`。**视频默认选择解析结果中的最高可用画质并显式传 `format_id`；用户明确指定档位时遵从。** 按完整宽高判断分辨率，竖屏 1080×1920 不能因高度超过 1080 被排除；不能盲用旧 `default_format`，也不能为兼容、省时或节省额度自行降清。
3. 展示真实标题、平台、作者（有则显示）、时长、所选完整宽×高与预计大小。未知或缺失的 0 值写“暂未获取”；只有画质标签时如实显示。图集注明真实类型；不展示流地址、Cookie 或认证参数。预计大小采用所选画质，已含音频时不重复相加。展示后简短说明开始下载分析并继续执行；不弹处理方式卡片、不倒计时、不等重复确认。
4. 实际下载工具 schema 支持时传入该 `parse_token`，缺失或过期先重新解析，保留最高画质或用户指定档位要求；不跨链接或鉴权来源复用。旧 schema 不发未知字段，仍严格核实实际尺寸。优先 `dogy_download_start`，用返回的 `task_id` 调 `dogy_download_status(wait_seconds=10)` 至 `completed` 或 `failed`，按真实阶段反馈进度；画面、声音下载百分比分别计，100% 不等于合并完成。仅旧程序缺少异步工具时使用 `dogy_download`。多链接顺序处理；指定 folder 须为绝对路径，省略时沿用 DOGY 保存目录。
5. **只有返回的绝对路径存在、实际视频宽高符合所选档位，才算下载达标。** 核对实际大小和分辨率，不只信请求档名。重新解析后目标档消失、发生下载错误或尺寸不符时，先查原因，再有限重试；保持原分辨率要求，格式 ID 改变时须核对同档。不能换成低清并称成功，也不能只说明降级就结束；无法取得时明确报告高清未完成及原因。
6. 达标后取得 `library_id`，缺少时登记一次；保留原片，按分析参考完成下列分析条件。最后使用归档后的真实路径，在聊天讲解并嵌入视频。

同批重复消息复用已存在下载/分析任务，不重复启动；改为分析时复用已保存且符合画质要求的原片。失败先查因，不把等待超时视为失败或用户取消。

用户明确“仅下载/不分析”时只下载、反馈进度和展示原片；只查看信息时只解析。明确取消时停止后续步骤，运行分析用取消接口；保留已保存原片。安装、更新、接入检查、检索和已完成任务查询不启动新下载。图集沿用原下载流程与逐图展示。

## 分析与完成条件

- **固定每 1 秒准备画面，明显变化处加密至约 0.5 秒，连续完全相同画面去重。** 不得因时长、额度、工具失败或手动兜底降低抽帧频率。最多 32 张概览只是阅读筛选，不改变底层取样策略。
- 优先 `dogy_analyze_start/status`；自动准备失败先按分析参考恢复。必要的手动处理必须复用 DOGY 同一抽帧算法、真实时间戳与连续去重；无法做到时记录缺口，不能用每 2 秒等稀疏抽帧冒充已完成要求。
- 读取全部分页转录（每页 limit=200），再读概览和关键时间范围密集画面。无音轨、转录失败、画面不清或未阅读部分如实记缺口；只将实际读过的文字和画面用于结论，不能称逐帧看完。
- 按参考保存笔记、标签、时间线、方法卡和真实 coverage 到本机 SQLite；保存成功后分类归档，再调用 `dogy_analyze_finish` 清理本任务临时材料。逐项核实保存、归档、清理结果；保留原片、旧资料与共享模型，不自行广泛删除目录。
- 分类只有一层：`AI与编程`、`设计与创作`、`知识学习`、`生活`、`娱乐`、`其他`。多主题用标签；不建平台或逐视频目录，用户另选分类时遵从。仅用户要求导出时生成单独文档，不在原片旁写分析中间文件。
- 优先复用已完成笔记及其真实覆盖；用户要求重新分析或覆盖不足时按参考使用 `force=true`。旧任务覆盖不能改写成新策略，下载登记和材料 ready 都不等于分析完成。

聊天交付必须包含：视频主题与主要内容、关键观点/方法/案例及适用条件、核对过的必要时间点、真实分析范围和缺口；区分作者说法、画面证据与 Agent 推断。简单短片不凑条数，详细笔记不能代替聊天讲解。失败或部分分析只讲已读内容，分别说明未完成阶段。

本机转录，不向分析服务发送原视频或提取音频；当前 Agent 理解转录文本与抽样画面，不能称完全离线。普通下载不自动分享，不添加网络下载链接。

在支持本地媒体的聊天中，**直接 `![视频标题](<最终绝对路径>)` 嵌入原视频，并保留“电脑打开原视频”链接**，无需用户再要求。图集逐图展示、手机入口及不支持预览时的处理见媒体参考。

## 查找已有视频与采用方法

1. 用 `dogy_library_search` 按描述检索，再 `dogy_library_get` 阅读来源、相关记录与时间点；无结果时尝试少量近义关键词，不只凭聊天记忆或虚构内容。此流程不刷新下载任务、不重下载或重转录原片。
2. 确定命中后核实 `exists=true` 和真实绝对路径，直接嵌入视频并保留“电脑打开原视频”链接及相关时间点；多条确定命中逐条展示。模糊候选先列候选供确认；用户只要文字或链接时遵从。原片缺失或客户端不支持预览时如实报告，不为展示另建分享或转换文件。
3. 关联 Codex / Agent 技术任务时也先检索。命中方法卡后说明来源、时间点、适用条件与验证状态，再询问是否采用；视频命令不因入库自动执行，作者演示不等于已在本机验证。资料库不修改模型权重，也不保证未加载插件的聊天自动知晓。
