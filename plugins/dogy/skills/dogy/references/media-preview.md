# 媒体展示与手机预览、下载

电脑使用本地媒体；用户明确要求手机查看、播放、下载，或已在本聊天要求后续媒体提供手机入口时，才启用临时 HTTPS 分享。普通下载不自动分享。

## 电脑聊天

电脑聊天沿用原始本地嵌入：`![图片或视频说明](<绝对文件路径>)`，路径取自真实下载结果；分类归档后使用最终路径。Windows 反斜杠可换为正斜杠，路径不要放入代码块。保留“电脑打开原视频”或“电脑打开原图”；图集目录标为“电脑打开原图文件夹”。Windows 路径、目录和 localhost 地址不能作为手机入口。

图集按确认存在的单图路径逐图嵌入；数量较多时分批展示并说明范围。不能只展示首张却声称已展示全部，也不能用目录链接替代逐图预览。

客户端不支持本地预览时如实说明。需要手机入口时按下方流程复用已下载原文件，不为预览重新下载、转换、上传成聊天附件或另建播放器服务。

## 手机入口的共同流程

1. 开始分享前简短说明：本次指定媒体通过 Cloudflare 临时转发，电脑须保持开机联网，约一小时有效；只开放本次媒体，不开放整个项目或保存目录。用户已明确要求手机入口后继续执行，不重复询问。
2. 调用真实可用的 `dogy_download_link(path=已保存媒体的绝对路径)`；视频用最终文件路径，图集用目录或单张原图路径。只传工具实际支持的参数。
3. 保存真实返回的链接和 `expires_at`，按下方视频/图片流程区分预览与下载。不能把强制下载地址标成播放地址，也不能把本地文件入口标成手机链接。
4. 检查 HTTPS 响应：预览应返回正确媒体类型和 `Content-Disposition: inline`，下载应为 `attachment`；HEAD 的 `Content-Length` 应与实际原文件大小一致。HEAD 不可用时用小范围 GET 检查，以 `Content-Range` 中的总大小核对原文件；此时 `Content-Length` 只是本次分段长度。避免为了验证再下载完整媒体。无法联网检查或检查失败时如实说明，不能声称已经验证。
5. 交付时说明实际到期时间及所在时区、电脑须在线；约一小时只是常规时长，不代替返回的到期时间；缺少 `expires_at` 时说明有效期暂未获取，不编造具体时间。未在用户手机验证，只能说“入口已生成并通过 HTTP 检查”，不能保证手机实际播放、内嵌或保存成功。

仅当前 MCP 连接已成功下载并登记的媒体可以分享；同盘分类归档的视频由工具核验身份。旧聊天的媒体被拒绝时，回到拥有该次下载的聊天生成入口；不为分享重新下载、不手工注册任意路径、不绕过身份校验。过期后可在拥有记录的连接再次调用同一工具；失败则说明原因。

## 手机视频：在线播放与下载

- 使用返回的 `download_url` 作为“手机下载原视频”；这是下载入口，不是在线播放入口。
- 返回 `preview_url` 时优先使用该真实值作为“手机在线播放”。
- **DOGY 1.0.0 兼容流程：** 视频结果可能只有 `download_url`，但临时媒体服务已支持 `preview.mp4`。仅当该工具本次返回的 URL 严格符合 `https://<临时域名>.trycloudflare.com/<32位字母数字、下划线或连字符令牌>/download.mp4` 时，保持域名和令牌完全不变，仅把末尾 `/download.mp4` 替换为 `/preview.mp4`，得到待验证的播放地址。这是已知服务路由的兼容处理，不添加工具参数、不猜测其他路径；其他形状的 URL 缺少 `preview_url` 时说明无法生成已知播放入口。
- 兼容播放地址验证通过后才能交付：检查 `Content-Type: video/mp4`、`Content-Disposition: inline`，再用 `Range: bytes=0-31` 请求确认返回 `206` 和匹配的 `Content-Range`；下载入口验证为 `attachment`。404、410、类型不符或验证未通过时不要把候选地址当成可用播放链接。
- 用户只要求播放时给“手机在线播放”；要求下载时给“手机下载原视频”；同时要求两者时并列给出，避免互相替代。
- 这是手机浏览器通过 HTTPS 读取电脑上的原视频，与聊天原生视频附件不同。不能声称已上传为聊天附件或恢复聊天原生播放器。响应正常但手机仍打不开时，记录客户端/格式限制，不擅自转码或承诺兼容所有设备。

交付示例（占位内容替换为本次验证结果）：

> [手机在线播放](已验证的播放地址) · [手机下载原视频](工具返回的下载地址)
>
> 链接有效至〔实际日期、时间、时区〕，电脑须保持在线。入口已通过 HTTP 检查，手机实际效果待确认。

## 手机图片与图集：原图预览与下载

- 图集读取 `items`，按真实文件名/原图序号逐项使用 `preview_url` 与 `download_url`。只展示已保存成功的文件；有下载失败时说明实际数量及缺失序号，不能把剩余文件重新编号后声称完整。
- 用户只要求查看时给“手机查看第 N 张原图”的 `preview_url`；要求下载时提供 `download_url`；同时要求预览和下载时使用“图片 / 手机查看 / 手机下载”表格。缺少某字段时说明缺少的入口，不猜测图片地址。
- 图片预览验证正确的 `image/*` 类型和 `inline`，下载验证相同类型和 `attachment`，长度与原图一致。客户端允许远程图片嵌入时可另用真实 `preview_url` 展示；电脑端保留原有本地嵌入。
- 保存到手机相册：打开原图后长按保存，或在分享菜单中选择“存储图像”。“手机下载”可能保存到“文件”而非相册；这两个去向应区分，不能承诺自动进入相册。客户端无保存选项时可在手机浏览器打开同一原图链接。
- 用户已要求手机入口时直接完成，不重新下载或压缩原图。分享错误或缺少入口时报告实际原因。

交付示例（每张原图一行）：

| 图片 | 手机查看 | 手机下载 |
|---|---|---|
| 第 N 张 | [打开原图](该图真实 preview_url) | [下载](该图真实 download_url) |

表格后给出相册保存方法、实际到期时间、电脑在线要求和手机端尚未验证的范围。
